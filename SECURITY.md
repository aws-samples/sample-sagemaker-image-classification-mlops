# Security

## Disclaimer

This repository is a **reference implementation and demo**, not a production
system and not a cleared clinical product. It is published to show how an
end-to-end MLOps lifecycle can be expressed in Terraform on Amazon SageMaker.

Do not deploy it as-is for clinical, diagnostic, or any other production
workload. Several architectural choices favour a readable public demo over
production hardening; they are listed under
[Known security considerations](#known-security-considerations) and
[Production Hardening](#production-hardening). Review both before adapting this
code.

Deploying this project creates real, billable AWS resources. See the Cost and
Cleanup sections of [README.md](README.md).

## Reporting vulnerabilities

If you discover a potential security issue in this project, notify AWS Security
via the [vulnerability reporting page](https://aws.amazon.com/security/vulnerability-reporting/)
or email <aws-security@amazon.com>. **Do not** create a public issue or pull
request describing the vulnerability.

## Data handling

- This project uses **public medical imaging datasets** and contains no PHI or
  PII. No dataset is committed to this repository; `data/` is gitignored.
- Dataset licensing is the user's responsibility. Confirm the terms of any
  dataset you supply, and do not commit PHI or PII.
- The datasets used carry no demographic metadata, so both the in-pipeline
  fairness gate and the scheduled fairness monitor operate on subgroup proxies
  (image magnification) rather than real demographic facets. Supply a real
  sensitive attribute before drawing any fairness conclusion.
- The scheduled fairness monitor needs confirmed diagnostic outcomes, which only
  a clinician can provide. It reads them from a `ground-truth` prefix that this
  project does not populate; until that feed exists the job finds nothing to
  score and publishes no metric. Predictions without a confirmed label are
  skipped, never inferred.

## Security controls implemented

- **Encryption at rest** with a project KMS customer-managed key across S3,
  CloudWatch Logs, SQS, Lambda environment variables, ECR, and the SageMaker
  endpoint's ML storage volume.
- **Encryption in transit**: `DenyInsecureTransport` bucket policies, HTTPS-only
  CloudFront viewer policy, TLS 1.2 minimum protocol version.
- **Least-privilege IAM**: no AWS-managed `*FullAccess` policies; actions are
  scoped to project-prefixed ARNs where AWS supports resource-level permissions;
  every `iam:PassRole` is constrained by `iam:PassedToService` and an ARN prefix.
- **Input validation** in the inference Lambda: base64 validation, image
  format and dimension checks, a decompression-bomb guard, and a payload size
  limit. Error responses are generic and leak no internal detail.
- **Blast-radius limits**: API Gateway throttling, Lambda reserved concurrency,
  and dead-letter queues on asynchronous invocations.
- **Audit**: CloudTrail with log-file validation; CloudTrail delivers to
  CloudWatch Logs.
- **Governance**: model promotion requires a human approval
  (`PendingManualApproval`), and low-confidence predictions can route to Amazon
  A2I for human review.
- **Supply chain**: monthly automated patching of the inference container image,
  with an SBOM generated by Syft on every image build.
- **CI security scanning** on GitLab CI via [.gitlab-ci.yml](.gitlab-ci.yml):
  SAST, IaC scanning, secret detection, and ASH. Locally, `checkov` reports 0
  failed checks and `bandit` reports 0 issues; every suppression in
  [.checkov.yaml](.checkov.yaml) and every inline `# nosec` states its reason.

## Known security considerations

These are deliberate demo trade-offs, not oversights. Each is accepted debt for
a public sample and should be revisited before any production use.

| # | Item | Severity | Impact if unaddressed | Production recommendation |
| --- | --- | --- | --- | --- |
| 1 | **Public, unauthenticated `/predict` and `/results` API** | Medium | Anyone who learns the endpoint URL can invoke it, creating cost and abuse exposure. Throttling and reserved concurrency limit but do not prevent this. | Add Cognito or IAM authentication and front the API with AWS WAF. |
| 2 | **ECR mutable image tags** | Medium | A compromised CI pipeline could overwrite an existing tag with a malicious image. Mutability is intentional so the patched inference image can re-publish the same floating tag as AWS ships DLC patches. | Use immutable, date-stamped tags and pin deployments to a digest. |
| 3 | **CodeBuild privileged mode** | Medium | Required for docker-in-docker to build the patched inference image; a compromised buildspec could escalate within the build environment. | Build images with a rootless builder such as Kaniko, or isolate image builds in a dedicated account. |
| 4 | **CloudWatch log retention of 30 days** | Low | Forensic investigation is limited to the last 30 days. Retention is short to control demo cost. | Set `log_retention_days` to 365 or more, or export logs to a SIEM. |
| 5 | **KMS key administration granted to the account root** | Low | Any sufficiently privileged IAM principal in the account could acquire key administration rights. | Scope key administration to a specific deployment role rather than the account root. |

Additional demo-scoped choices, each documented with its rationale in
[.checkov.yaml](.checkov.yaml): no VPC for the Lambda functions, no S3
cross-region replication, no API Gateway or CloudFront response caching (medical
inference responses must never be served to another caller), the default
CloudFront certificate, no Lambda code signing, and SageMaker network isolation
disabled so trainers can fetch ImageNet weights.

## Production Hardening

Before adapting this project for production, at minimum:

1. **Authenticate the API.** Add Cognito or IAM authorization to API Gateway and
   attach an AWS WAF web ACL to both the API and the CloudFront distribution.
2. **Move into a VPC.** Place the Lambda functions and the SageMaker endpoint in
   private subnets with VPC endpoints for S3, SageMaker, and Bedrock.
3. **Make container tags immutable.** Enable ECR tag immutability, pin
   deployments by image digest, and enable enhanced scanning.
4. **Extend log retention.** Raise CloudWatch retention to a year or more, or
   ship logs to a SIEM, to meet healthcare audit expectations.
5. **Scope KMS administration.** Replace the account-root key administrator with
   a dedicated deployment role, and enable key rotation.
6. **Harden the build.** Replace privileged CodeBuild with a rootless image
   builder, and enable Lambda code signing.
7. **Enable SageMaker network isolation.** Set `enable_network_isolation = true`
   and supply pre-downloaded model weights through the weights channel.
8. **Add DR.** Enable S3 cross-region replication and versioning on buckets whose
   contents cannot be regenerated.
9. **Complete the compliance review.** For any clinical use, complete the
   applicable regulatory assessment (for example HIPAA or the EU AI Act) and
   execute a Business Associate Addendum with AWS where required. Bias and
   explainability reports in this project are illustrative, not a substitute for
   clinical validation.

## Resource cleanup

Destroy in reverse dependency order. Buckets must be emptied before deletion.

```bash
# 1. Remove non-Terraform-managed data and resources
./ops-scripts/cleanup_all.sh

# 2. Destroy the roots in reverse order
cd stack-inference && terraform destroy
cd ../stack-training && terraform destroy
cd ../stack-cicd && terraform destroy
cd ../stack-backend-setup && terraform destroy   # last - holds remote state
```

Confirm in the console that the SageMaker endpoint and the MLflow tracking server
are gone, since these bill continuously. The drift and fairness schedules are
Terraform-managed and go with `stack-inference`.

## Dependencies

- **Terraform** `~> 1.15`, with the AWS provider `~> 6.0` (both pinned in each
  stack's `versions.tf`).
- **Python** 3.13 or later, as declared in `pyproject.toml`. Training and
  inference containers derive from AWS Deep Learning Containers; the inference
  image is rebuilt monthly to pick up base-image patches, with an SBOM published
  per build.
- Python tooling (`ruff`, `bandit`, `checkov`) is used for linting and scanning
  and is not deployed with the solution.

Keep dependencies current when adapting this project. Review the SBOM in the
project's SBOM bucket for the exact contents of a built inference image.
